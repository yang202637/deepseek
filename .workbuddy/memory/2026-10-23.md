## Claude Code CLI 卸载后重装（环境维护）

**背景**：用户先要求卸载 Claude Code CLI（截图里官方卸载器报错"无法自动卸载"），随后改主意要求重装。

**安装位置**：`C:\scoop\apps\nodejs\node-v24.20.0-win-x64`（scoop 装的 Node v24.20.0 的全局 npm prefix）。
注意当前 shell 里 `node`/`npm` 指向 WorkBuddy 托管的 `~/.workbuddy/binaries/node/versions/22.22.2-6`，**两者不是同一套**，操作 scoop 的包必须显式调用 scoop 目录下的 `node.exe + node_modules/npm/bin/npm-cli.js`。

**卸载**：`npm-cli.js uninstall -g @anthropic-ai/claude-code`（1 个包，3 秒）。

**重装踩坑（重要，可复用）**：
1. 首次 `npm install -g` 耗时 12 分钟，且 postinstall 被 npm 11 的 allowScripts 机制拦截 → `claude` 命令报 "native binary not installed"。
2. 手动跑 `install.cjs` 报错找不到 native package，因为 optional dep 目录里只有 `claude.exe`、缺 `package.json`（`require.resolve` 失败）。
3. 补上 package.json 后二进制落位，但执行报 `Exec format error` / "not a valid application for this OS platform"。
4. **真正的根因**：`NODE_OPTIONS=--require=...workbuddy.../node-language-shim.cjs` 劫持了 npm 的 `fs.rm`（转调 safe-delete / 回收站），导致解包 285MB 的 native 包时中断并留下**截断文件**——PE 头声明需要 298,613,760 字节，实际只有 102,688,035 字节。

**最终解法**：
```bash
cd "C:/scoop/apps/nodejs/node-v24.20.0-win-x64"
env -u NODE_OPTIONS ./node.exe ./node_modules/npm/bin/npm-cli.js \
  install -g @anthropic-ai/claude-code --allow-scripts=@anthropic-ai/claude-code
```
清掉 `NODE_OPTIONS` + 显式 `--allow-scripts` 后，**17 秒装完、零警告**，`claude --version` → `2.1.309 (Claude Code)`。

**经验**：在这台机器上用 npm 装带大体积 native 二进制的全局包，务必 `env -u NODE_OPTIONS`，否则容易因 shim 干扰产生静默截断的坏二进制。校验方法：用 Python 解析 PE 区段表，比对 `max(rawptr+rawsize)` 与文件实际大小。

**保留未动**：`~/.claude/`（1.2GB，含 downloads/skills/projects 会话历史）与 `~/.claude.json`（132KB），登录凭据 `.credentials.json` 完好，重装后配置直接继承。IDE 侧插件（VS Code 1 个 + JetBrains 四套 IDE 各 9 个）仍在，未卸载。
